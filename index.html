The problem with enterprise search

Your organization's knowledge is scattered across SharePoint, Confluence, Google Drive, Jira, Salesforce, and a dozen other systems. Existing search tools — Coveo, Glean, Elastic, Microsoft Search — index this content as undifferentiated text.

They can find documents containing a term. They cannot answer questions about the structured information within and across those documents.

What Trellis does differently

Trellis doesn't just index text. It classifies each document by type, applies a domain-specific ontology to extract entities and relationships, resolves duplicates, and builds a unified knowledge graph across all your systems.

The result: a semantic layer where a company appearing in a procurement notice, a contract, and a corporate report is one node — with edges to every related entity.

How it works

Five stages from raw document to queryable graph.

1
Connect
Source connectors authenticate and enumerate documents from SharePoint, Confluence, Google Drive, Jira, Salesforce, and others. Incremental sync tracks changes.
2
Classify
Each document is assigned a type — contract, regulation, report, specification. Rule-based or LLM classification. Multi-type documents are segmented.
3
Extract
Per-type ontologies define what to extract: entities, attributes, relationships. LLM extraction with confidence scoring. YAML-driven, no code changes.
4
Resolve
Extracted entities are matched to existing graph nodes. Exact ID match, fuzzy name match, LLM disambiguation. One company = one node across all sources.
5
Query
BM25, vector, and graph traversal fire in parallel. Reciprocal Rank Fusion merges results. LLM synthesizes a cited answer from combined context.
